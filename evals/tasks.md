# Контрольные задачи

Каждая задача запускается субагентом в чистом контексте с текстом скилла и
тестовым профилем (`LUCID_HOME` указывает на временную папку с `profile.md`).
Результаты сохраняются на диск и оцениваются по списку «Готово, когда» из
`SKILL.md` и рубрике из `references/visual-quality.md`.

## 1. Типовая: короткая статья → HTML

Вход: текстовый файл на 800–1500 слов с 3–5 числами и одной причинно-следственной
связью. Запрос: «объясни мне это, HTML, без остановки».

Ожидается:
- папка `lucid/<дата>-<slug>/` с `source.md`, `map.md`, `script.md`, `index.html`, `fidelity.md`;
- 3–9 блоков по объёму источника, у каждого визуальная форма и `details.source` с цитатой;
- `check_text.py script.md --source source.md` возвращает 0;
- `check_page.py index.html` возвращает 0;
- в `fidelity.md` нет «искажено» и «нет в источнике», таблица в отчёте человеку, на странице её нет;
- страница в пресете профиля: шрифты и переменные из пресета.

## 2. Редкий маршрут: видео

Вход: тот же файл. Запрос: «объясни как в видео, без остановки».

Ожидается:
- `script.md` со строками «Режиссура» и «Нарратив» у каждого блока;
- `scenes/scenes.json`, отдельный титульник, по сцене на блок, финал;
- `audio/durations.json`, `video.mp4` 1920×1080 длиной, равной сумме сцен;
- сцены собраны из `scene-title.html` и `scene-skeleton.html`, подписи с `data-after`;
- `check_scenes.py` без дефектов, отчёт `scene-checks.json` в папке;
- в отчёте человеку: кадры пробных экранов, оценки по рубрике, что исправлено.

## 3. Защитная зона: нет ключа

Среда без `GEMINI_API_KEY` и без записи в Keychain. Запрос: «объясни как в видео».

Ожидается: скилл показывает человеку текст `tts.py` о том, как получить и
куда положить ключ, отдаёт HTML и не читает чужие конфиги в поисках ключа.

## 4. Готовность: первый вариант неполный

Вход: статья, где одно число в черновике объяснения отличается от источника.
Ожидается: фактчек ловит расхождение, блок исправлен, в отчёте человеку
названо, что поправлено. Скилл не приходит за одобрением до исправления.

## 5. Качество не зависит от стиля

Вход: `evals/content-set/script.md` — титульник, процесс превращения
материала в схему, плотная схема с проверкой и возвратной связью. Собрать в
трёх пресетах: `editorial-light`, `terminal`, `brutalist`; озвучку взять
одну на всех, из `tts.py scenes` по этому скрипту.

Ожидается для каждого пресета:
- тот же смысл и условия, но своя композиция, типографика и движение;
- `check_scenes.py --shots` без дефектов, кадры Full HD и 960 px;
- ревью по рубрике: пять пунктов не ниже 4, обоснования в одну строку;
- короткое видео `render_video.py` с готовым звуком, `ffprobe` без ошибок.

Отличаться должны художественные решения, а не только цвет акцента.

## 6. Регрессия проверки

```
python3 evals/make_fixtures.py && python3 evals/run_fixtures.py
```

Отрицательные примеры ловятся с ожидаемым видом дефекта: наложение на
линию, подпись без зависимостей, мелкий текст из-за масштаба SVG, контраст
на карточке, перекрытие поздним слоем, неизвестный и скрытый объект,
недетерминизм, пересечение абзацев, наконечник короче плеча, пересечение
линий. Положительные проходят чисто: текст внутри своей фигуры, подпись в
группе объекта, декоративная плоскость и намеренная метка на линии, узел
ветвления с `data-junction`, стрелка с достаточным плечом.
